Spike report · Unity 6000.6.6f1 · 2026-11-03

Slice Layout in Unity

The .NET build and the architecture tests are the authority for dependencies. Unity must only compile the code. Layout B (the .csproj files, no asmdef) does this: Unity compiles all module files into Assembly-CSharp. Layout B needs one setting: dotnet must write obj and bin to folders that Unity does not import. The real vsa-template code does not compile in Unity in any layout: it needs C# 10 to 12 and the VSA and EF Core packages.

Spikes: Card-Framework/Assets/Spikes/SliceLayout/ (A, asmref), Assets/Spikes/SliceLayoutFlat/ (B, flat) and Assets/Spikes/SliceLayoutBoth/ (C, both) · Evidence: Logs/gate/history/<run>/report.json

1 · Assumption

Unity puts each file in an assembly by folder only. It ignores .csproj files and MSBuild globs. Without an .asmdef, all scripts go into Assembly-CSharp.

IDHypothesis
H1An .asmref in a slice subfolder adds its files to an assembly in a different folder.
H2The asmdef references keep the vsa-template boundaries.
H3Two modules can handle each other's events with no reference cycle.
H4The generated IDE projects show the correct files.
H5Without asmdef or asmref, Unity compiles the code into one assembly and ignores the .csproj files.
H6The vsa-template code compiles in Unity as it is.
H7A .csproj and an asmdef in the same folder work together: each build reads only its own file.

5 · Opinion

GO Use layout B. The .NET build and the architecture tests enforce the dependencies. Unity only compiles the code.

TopicA · asmrefB · flatC · both
Boundaries in .NETNot builtEnforcedEnforced
Boundaries in UnityEnforcedNoneEnforced
Files for Unityasmdef, asmrefNoneasmdef, asmref
Reference lists to keep equalOneOneTwo
Asmdef code sees module codeYesNoYes
Build output settingNot neededNeeded (N6)Needed (C4)

Layout B has three conditions:

  • Dotnet writes to obj~/ and bin~/. Without this, Unity does not compile (N5).
  • Module code uses C# 9 and no implicit usings, and the VSA packages are available to Unity (N3, N4).
  • No asmdef code calls module code. Framework assemblies, test asmdefs and packages cannot reference Assembly-CSharp.

If asmdef code must call module code, use layout C. Its asmdefs then exist only for that reference, and the .NET build stays the authority.

Open questions

  • Must all module code compile in Unity, or only the contracts?
  • How do the VSA.* packages reach Unity: UPM source, or DLLs?
  • Does VSA.Sdk write the asmdef and asmref files, or does a check compare them with the csproj files?
  • Does the Roslyn analyzer (VSA1002, VSA2001) run in Unity with the RoslynAnalyzer label? This spike did not test it.
