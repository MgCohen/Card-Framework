# Core Glossary

This glossary establishes working language for the Card Framework. Terms may be refined later, but new research docs should use these meanings unless they explicitly propose a change.

## Foundational Terms


| Term            | Short Definition                                                              | Examples / Notes                                                                                                         |
| --------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Game            | The authored ruleset and content domain for a playable card-based experience. | Magic-like TCG, Slay-like deckbuilder, Stacklands-like spatial sim, card-based RPG or board game.                        |
| GameDefinition  | Top-level bundle for a game-mode variant. Carries `Rules` (a `GameRulesDefinition`), `SharedZones` (game-level zone layout), `CardCatalog` (the set of `CardDefinition`s usable in this mode), `DefaultPlayerDefinition` (applied to all player actors; per-actor overrides via `MatchSetup`), and `GetInitialSlices()` (game-singleton slices). Implements `ISliceProvider`. | One per game-mode variant (Magic Standard / Commander / Pauper, Pile Counter Easy / Hard). Asset-friendly; serializable. The factory consumes it as the `Rules`-replacing parameter of `MatchSetup`. See [Game Definition](features/engine/models/06-game-definition.md). |
| Session         | One running simulation instance of a game definition.                         | Match, combat encounter, full roguelike run, board simulation, replayed scenario, test case.                             |
| Actor / IActor  | `interface IActor { ActorId Id; }` — anything that can own things in the simulation. | Concrete actors are either entity-backed (`Player : EntityInstance<PlayerDefinition>, IActor`) or lightweight non-entity records (`World`, `Environment`, `Bot`, `Market` — `sealed record World(ActorId Id) : IActor`). Actor's role stays narrow ("anything that can own things"); subject to revisit if a richer surface emerges. |
| ActorId         | Identifier of an actor (`Identifier<Actor>`). Distinct from any entity ref.     | Used for command attribution, history envelopes (`HistoryEnvelope.actor`), and per-actor action queries (`GetActionsFor(ActorId)`). System / AI / environment actors have an `ActorId` but no entity ref. |
| Player          | `class Player : InstanceWithSlices<PlayerDefinition>, IActor` (unsealed) — framework-provided baseline subtype representing a seated participant with entity-backed variables. Carries typed `Ref<Player> SelfRef` and `ActorId`. | Use when a game has player seats, ownership, priority, score, deck ownership, or client association. Per-player game state lives in `EntityState` (variables — life, mana count, energy) and in slices declared by `PlayerDefinition.GetInitialSlices()` keyed at `player.SelfRef`. Other Actor kinds (`World`, `Environment`, `Market`, `Bot`) are non-entity-backed `IActor` records. See [Player Model](features/players/models/01-player-model.md) and [Game Factory](features/engine/models/05-game-factory.md). |
| PlayerDefinition | Authored base data for a player kind. `PlayerDefinition : DefinitionWithSlices` (which inherits from `Scaffold.EntityDefinition` and implements `ISliceProvider`). Declares default variable values (StartingLife, StartingMana, etc.) via the entity-bridge variable bag and per-player non-variable slices via `GetInitialSlices()`. Also declares the player's `PerPlayerZones` layout block (hand, deck, discard). | Symmetric games use a single `DefaultPlayerDefinition` on `GameDefinition`; asymmetric games (different heroes/roles) override per-actor via `MatchSetup.PlayerDefinitionOverlay`. See [Player Model](features/players/models/01-player-model.md). |
| Owner           | The Actor (`IActor`) that owns a handle. Named concept, not a framework type. | Implementation: an `IActor`-typed value in `OwnershipState` keyed by the handle's `Reference`. Tracks runtime mutable ownership (primarily card ownership). Zone assignment is structural — declared in `GameDefinition.SharedZones` / `PlayerDefinition.PerPlayerZones`, not in `OwnershipState`. |


## Entity Model


| Term                | Short Definition                                                                                 | Examples / Notes                                                                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entity              | Any runtime object the simulation may need to reference.                                         | Card instance, zone instance, player/actor, relic, equipment, resource, villager, enemy, stack entry, token, card pack. Every entity should have a base definition.       |
| Definition          | Authored base data shared by instances.                                                          | Fireball card definition, Iron Sword equipment definition, Hand zone definition, Villager definition, Berry Bush resource definition. Definitions should have stable IDs. |
| Instance            | Runtime entity created from a definition.                                                        | `Instance = definition + Ref<TInstance> + variables + modifiers`. Concrete shape is `EntityInstance<TDef>` with typed `SelfRef`. Zone movement preserves the same instance by default. |
| Identifier\<T\>     | Base record providing both value and reference utility for stable ID types in the framework.        | Used for `DefinitionId`, `ActorId`, chain IDs, etc. Reserved for boundaries — serialization, persistence, network, type-mismatch fallback. Within the simulation, prefer the object (per [ADR-0005](decisions/0005-objects-over-ids.md)). Runtime-entity identity has migrated off `Identifier<Instance>` to `Ref<T>` / `Reference`; full migration of remaining `Identifier<T>` users is a separate cascade. |
| Reference           | Abstract record base in `Scaffold.States`; the polymorphic addressable type. Replaces the old `IReference` marker. | Polymorphic APIs that take "any addressable thing" type the parameter as `Reference`. Concrete identities are typed `Ref<T>` subrecords. |
| Ref\<T\>            | Sealed-record subtype of `Reference`, backed by `Guid`. Typed runtime identity for catalog-registered handles (`Ref<Card>`, `Ref<Zone>`, `Ref<Player>`). | Allocated via `store.Catalog.AllocateRef<T>()`; resolved via `store.Catalog.Resolve(r)`. Stable for the lifetime of the handle. Distinct from `CardRef`, which is the privacy-rotating client-visible ref. |
| ICatalog            | Sub-property on `Store` (accessed as `store.Catalog`) providing register/resolve for arbitrary objects keyed by `Ref<T>`. In-process side-state on the Store; not snapshotted. | `AllocateRef<T>()`, `RegisterAt(ref, obj)`, `Resolve(ref)`. Used by `StoreEntities.Spawn<TDef>` and any other handle-registering surface. |
| ICatalogged         | Opt-in interface for objects that carry a stable cross-run `Guid Key`. | Lets the catalog round-trip the same handle across save/load. Cards/zones/players become `ICatalogged` once persistence is wired. |
| EntityInstance\<TDef\> | Single entity handle class in `Scaffold.Entities`; pairs `(Definition, Storage)`. Identity-free at the base. External — the framework subclasses via `InstanceWithSlices<TDef>`. | Concrete framework subclasses (`Card`, `Zone`, `Player`) inherit through `InstanceWithSlices<TDef>` and add typed `Ref<TSubclass> SelfRef`. Storage is `IEntityVariableStorage` — typically `StoreVariableStorage(store, selfRef)` for store-backed variables, or `LocalVariableStorage(parent)` for overlays. Replaces the old `StateEntity<TDef>` / `BaseEntityInstance<TDef>` / `IReadOnlyEntity` / `IMutableEntity` family. |
| DefinitionWithSlices | Card Framework parent (`: Scaffold.EntityDefinition, ISliceProvider`). Consolidates the slice-provider contract on the Definition side; CardDefinition / ZoneDefinition / PlayerDefinition inherit from it. | Default empty `GetInitialSlices() => Array.Empty<BaseState>()`; concrete subclasses override to declare per-instance slices. `GameDefinition` is independent of `Scaffold.EntityDefinition` and implements `ISliceProvider` directly. |
| InstanceWithSlices\<TDef\> | Card Framework parent (`: Scaffold.EntityInstance<TDef>, ISliceProvider`). Consolidates the slice-provider contract on the Instance side; Card / Zone / Player inherit from it. Exposes `Definition` as `protected`. | Default `GetInitialSlices()` delegates to the (protected) definition's slices. Concrete subclasses are unsealed (project convention); games may subclass for typed re-export of authored Definition fields, with a discouragement note in framework docs. |
| EntityState         | Sealed record slice `(BaseValues, ModifierStacks) : State` in `com.scaffold.entities.states`. Pure data with functional `With*` updates and pure-read methods (`TryGetBase`, `GetModifiers`, `Variables`). | Replaces `EntityVariableState`. Mutators use `Mutator<EntityState, TPayload>` with immutable-return semantics. Seven payloads: `AddModifierPayload`, `RemoveModifierPayload`, `SetBaseValuePayload`, `AddEntityVariablePayload`, `RemoveEntityVariablePayload`, `RemoveModifiersBySourcePayload`, `ClearModifiersPayload`. |
| StoreVariableStorage | ~90 LOC `IEntityVariableStorage` adapter that delegates reads to `EntityState` slice methods and dispatches writes as payloads. `Parent => null`. | Replaces the older 422-LOC version that held a per-variable subscription cache. The cache is gone; subscribe via `store.Subscribe<EntityState>(entityRef, ...)` for change notifications. |
| LocalVariableStorage | Overlay implementation of `IEntityVariableStorage` with an optional `Parent`. Reads chain to the parent on miss; modifier folds union both layers. | Used for previews, hypothetical states, and effect-scoped overrides without committing to the Store. |
| ModifierSource      | `(Reference Source, int Order)` tuple identifying who emitted a modifier. `Source` is nullable. | Used by `RemoveModifiersBySourcePayload` to bulk-remove all modifiers a given source emitted. Constructed as `new ModifierSource(card.SelfRef, order)`. Replaces the old `ModifierSource(InstanceId)` shape. |
| StoreEntities.Spawn | Extension method on `Store` that allocates a `Ref<EntityInstance<TDef>>`, registers an empty `EntityState` slice, constructs the handle with `StoreVariableStorage`, and registers the handle in the catalog. Returns `(Instance, Ref)`. | Replaces `EntityStateFactory.Create`. Typed subclass spawn helpers (`Card.Spawn`, etc.) wrap this and return the typed handle. |
| ISliceProvider  | Parameterless interface: `IEnumerable<BaseState> GetInitialSlices()`. Reached on framework Definition kinds (`CardDefinition`, `ZoneDefinition`, `PlayerDefinition`) via the parent `DefinitionWithSlices`, and directly on `GameDefinition`. Reached on framework Instance kinds (`Card`, `Zone`, `Player`) via the parent `InstanceWithSlices<TDef>`, with the instance defaulting to delegate to the (protected) definition. | The factory walks definitions/instances at `Build` and installs returned slices, keying entity-instance slices at `instance.SelfRef` and game-singletons without keying. **Slices don't carry their primary key** — storage is keyed externally by the factory. Concrete subclasses override `GetInitialSlices()` to declare per-spawn or per-game initial state. See [Game Definition](features/engine/models/06-game-definition.md). |
| Definition ID       | Stable authored identifier of a definition. Typed as `Identifier<Definition>`.                  | Used for save/load, replay, debugging, networking, validation, and cross-reference from instances to definitions.                                                         |
| Variable            | Key-value entry on a definition or instance.                                                     | `VariableKey -> VariableValue`. Keys like `cost`, `attack`, `zone`, or `recipe_progress` are game/preset/schema-defined, not hardcoded by the base framework.             |
| Base Value          | Value supplied by the base definition before runtime changes.                                    | Example: a card definition has base `cost = 3`.                                                                                                                           |
| Modifier            | Runtime adjustment applied to an instance or variable.                                           | Cost reduced this turn, attack from equipment, Retain gained in a zone, work speed from a tool.                                                                           |
| Effective Value     | Final calculated value after base values, modifiers, attachments, external effects, and context. | Example: base attack 2 + sword 3 + aura 1 = effective attack 6.                                                                                                           |
| Relationship        | Directed or structured link between entities.                                                    | Owner, controller, in-zone, attached-to, equipped-by, stacked-on, targeting, source-of-effect, parent-child.                                                              |
| Attachment          | Instance connected to another instance through a relationship.                                   | Equipment attached to a character, aura attached to a card, token stacked on a resource. Attachments are usually their own instances.                                     |
| Composition Handler | System that calculates meaning from multiple related instances.                                  | Equipment stats, aura bonuses, stack recipe progress. May be game-specific or preset-specific.                                                                            |
| Card                | Framework handle for a card-shaped game entity. `class Card : InstanceWithSlices<CardDefinition>` (unsealed) carrying typed `Ref<Card> SelfRef`. Lives in the catalog (resolved via `store.Catalog.Resolve(cardRef)`); the `CardRef → Ref<Card>` mapping lives in `CardMapState`. | Thin handle (no mutable data on the class itself); variables/modifiers via `Storage` (the `IEntityVariableStorage` adapter), current public ref via `card.GetRef(state)`, owner via `card.GetOwner(state)`. Per-card-type variants (Fireball, Goblin, etc.) are different `CardDefinition` instances, not different C# subclasses (data-driven). Card identity equality is via `SelfRef`. See [Card Model](features/cards/models/01-card-model.md). |
| CardRef             | Temporary reference to a card. Rotates on every move and on every visibility transition. Not an `Identifier<T>`. | `readonly record struct CardRef(Guid Value)`; `CardRef.NewRef()` factory. Used as the `CardMapState` key, in `ZoneContentsState`, in client-visible projections. The framework's privacy mechanism — observers see refs change but receive no data they aren't allowed to see. |
| CardMapState        | Slice mapping `CardRef → Ref<Card>` plus the parallel reverse index `Ref<Card> → CardRef`. The privacy-rotation indirection layer. | Two `ImmutableDictionary` fields kept in sync by mutators. Snapshot/rollback works for free. Reverse index makes `RefOf(card)` O(1). The live `Card` handle is resolved one further hop via `store.Catalog.Resolve(refOfCard)`. The `Card` handle and its `Ref<Card>` are stable; only the public `CardRef` rotates. |
| CardRegistry        | **Retired.** Removed by the open-seams design pass (Q5). `store.Catalog` is the single registry for stable handle resolution; `Ref<Card>`'s typed parameter enables `store.Catalog.Resolve(refOfCard)` directly with no separate registry. Resolution from a public `CardRef`: two-hop via `CardMapState` then `Catalog`. | Listed in Retired terms. |
| OwnershipState      | Generic framework slice mapping `Reference → Actor`. Applicable to any catalog-registered handle (Cards, Zones, Players). | Reads through `card.GetOwner(state)` or `zone.GetOwner(state)`. Handles without an owner have no entry in the slice. |
| CardVisibilityState | Per-card visibility slice keyed by `Ref<Card>`, holding `CardVisibility` enum overrides. | Absent entry = use the zone's policy default. |


## Zones And Location


| Term            | Short Definition                                                                       | Examples / Notes                                                                                                                                                                         |
| --------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Zone            | Thin domain handle (`class Zone : InstanceWithSlices<ZoneDefinition>`, unsealed) grouping cards. Carries typed `Ref<Zone> SelfRef` and `(Definition, Storage)`; owner via `OwnershipState`; contents via `ZoneContentsState`. Lives in the catalog (`store.Catalog.Resolve(zoneRef)`). | Deck, hand, discard, battlefield, rules stack, physical stack, shop row, production slot. **Not** card packs (entities with generator effects), reward offers, or drafts (decisions). Zones do not have stats; stat-bearing things are not zones. |
| ZoneDefinition  | Authored config for a zone type — capacity, ordering rules, insertion behavior, default visibility policy. | Hand definition, deck definition, MTG-stack definition. Different zone types vary by definition data, not by class hierarchy. |
| ZoneContentsState | Generic framework-owned slice keyed by zone, holding ordered membership as `ImmutableList<CardRef>`. | Flat list of `CardRef`s. Refs rotate on every move (per Card Model). Slot keys, group keys, spatial coordinates, and other per-entry structure are not pre-defined hooks — a game adds those fields on its own design pass when forced by real requirements. |
| Zone Membership | Zone-owned state saying a card is currently in a zone. Canonically lives in `ZoneContentsState` as a list of `CardRef`s. | Does not define the card. It can trigger rules and may have ordering inside the zone. |
| Zone Movement   | State change that moves an entity between zones or changes its position within a zone. | May trigger effects, update visibility, change modifiers, or be blocked. Does not create a new instance by default. |
| Position        | Address, ordering, or game-specific placement inside a zone.                           | Top of deck, third card in hand, battlefield slot, stack depth. World-space placement is only core simulation data if a game-specific spatial system makes it so.                         |
| Stack           | Ambiguous term that must be qualified by context.                                      | Could mean Magic-like rules stack, physical card stack, or scheduler data structure.                                                                                                     |
| Membership Visibility | Whether an actor can know which instance IDs are in a zone and how they are arranged. | Example: a player sees their hand contents; an opponent may only see a count. |
| Detail Visibility | Whether an actor can resolve definition and variable data for a known instance ID. | Example: a face-down card may be visible as an instance but hide its definition and variables. |
| Card Visibility | Per-card runtime flag enum `{ Hidden, VisibleToOwner, VisibleToAll }` on `CardVisibilityState` keyed by `Ref<Card>`. Absent entry = use zone policy default. Defined in [Card Model § Card Visibility](features/cards/models/01-card-model.md). | Override on top of zone definition's policy. `VisibleToOwner` requires Owner; collapses to `Hidden` if no Owner. Read via `card.IsVisibleTo(state, actor)`. Mutated via `SetCardVisibilityMutation`. |
| ZoneVisibilityPolicy | Sealed record hierarchy on `ZoneDefinition` declaring the default visibility for the zone. Named cases (`AllPublic`, `AllHidden`, `OwnerSees`, `OwnerSeesOthersCount`, `OwnerCountOthersNothing`) plus a `Custom(Func<...>)` escape hatch for game-specific resolution. Pattern-matched in `card.IsVisibleTo`. Defined in [Zone Model § Zone visibility policy](features/zones/models/01-zone-model.md). | Hand zone = `OwnerSeesOthersCount`. Deck = `OwnerCountOthersNothing`. Battlefield = `AllPublic`. Custom serialization is deferred — see `bl-zone-visibility-custom-policy-serialization` in `OPEN-ITEMS.md`. |
| SetCardVisibilityMutation | Composite `CompositeAction` collapsing what would otherwise be separate Hide and Show mutations. Carries `(Card, NewRef, CardVisibility)`. | Static factories: `Hide(card)`, `ShowAll(card)`, `ShowToOwner(card)`. Every transition rotates the `CardRef` (conservative privacy policy). |
| ~~Ephemeral Instance ID~~ | **Deprecated.** Was a per-actor transport alias under the original Q6.2 lock; superseded by server-side `CardRef` rotation per [ADR-0008](Product/decisions/0008-zone-visibility-model.md). | The framework no longer maintains a per-actor alias map. Privacy across reveal cycles is achieved by `CardRef` rotation that all observers see. |
| Zone Capacity | Default organizational limit for a zone. | Capacity can be overridden or ignored by game/action rules when an effect forces a move via `InsertCardPayload { BypassCapacity = true }`. |
| InsertCardPayload | Single payload for zone insertion with optional override fields: `{ Zone, Card, Position, BypassCapacity }`. | `Position` is a sealed record hierarchy: `DefaultPosition`, `AtTop`, `AtBottom`, `AtIndex(int)`. Static factories provide call-site sugar. Used inside the composite `MoveCardMutation`. |
| MoveCardMutation | Composite `CompositeAction` encapsulating a remove-then-insert as one logical zone move. Carries `(Card, NewRef, Source, Destination, Position, BypassCapacity)`. | Every move rotates the `CardRef` (per the conservative privacy policy). Internally: removes old ref from source's `ZoneContentsState`, rotates `CardMapState`, inserts new ref into destination at `Position`. Static factories: `MoveCardMutation.AtTop / AtBottom / AtIndex`. Replaces the older `RelocateInstanceMutation` name. |


## Rules And Flow


| Term | Short Definition | Examples / Notes |
| ---- | ---------------- | ---------------- |
| Intent | Informal term for what a player or system wants to do. Not a runtime type. | Use `PlayerIntent` for the structured form. |
| PlayerIntent | Structured player-originated intent submitted to the engine. | Drag card, select card, pass turn, select option. Replaces `Request`. |
| IntentResult | Structured outcome returned to the caller after a `PlayerIntent` is submitted. | Accepted (with chain ID) or rejected (with reason code). |
| IntentMapper | **Retired as a global service** (2026-05-11 per [ADR-0012](decisions/0012-presentation-per-state-view-models.md)). Was a single gateway-side component switching on every `ActionTemplate` subtype. Replaced by **per-VM `Map(intent) → GameCommand`** on `MatchStateViewModel<TState>`. Each VM owns a small intent map scoped to its mode; in request-mode the VM returns a `Response` instead of a normal `GameAction`. Canonical Model archived at [`features/actions/archive/02-intent-mapper.md`](features/actions/archive/02-intent-mapper.md). | See full retired-term entry in §Retired terms below. |
| AvailableAction | Optional engine-exposed affordance that UI may highlight or present. | This card can be played, this target is available, this ability can be activated. |
| AvailableActionsSnapshot | **Retired / subsumed.** Was a read-only artifact published by `GameRulesRuntime` from inside `Evaluate`. Replaced by **`MatchState.Actions`** (`IReadOnlyList<Type>` carried on the active match state, per [ADR-0009](decisions/0009-engine-as-fsm.md)) + per-state VM observables for the rich UI projection (per [ADR-0012](decisions/0012-presentation-per-state-view-models.md)). The typed-descriptor wire form (`ActionTemplate`, etc.) is deferred — `Actions` stays as a type list for now. Canonical Model archived at [`features/actions/archive/05-available-actions-snapshot.md`](features/actions/archive/05-available-actions-snapshot.md). | See full retired-term entry in §Retired terms below. |
| Command | High-level game command or low-level state command, depending on lane. | Game command: deal damage; state command: set variable. Naming still needs refinement. |
| GameCommand | Abstract base for all pipeline-dispatchable types: `GameAction`, `GameSignal`, `Request<TResponse>`, `Response`. **4-sibling family** per [ADR-0013](decisions/0013-engine-pipeline-orchestration.md). All four are queued through `engine.Dispatch` / `scope.Dispatch`; all four participate in the trigger fold (except `GameSignal` skips the validator chain + handler — folds only). | Not directly instantiated. Subtypes carry different execution semantics. The pre-cascade `CompositeAction` sibling retires; its replacement `CompositeMutation` lives outside the `GameCommand` hierarchy and is reached via `scope.Execute`. |
| StateMutation | Low-level already-approved state mutation. | Insert into zone, set variable, add modifier, create instance. Replaces `StateCommand`. |
| StateChange | A `HistoryEntry` subtype recording a concrete state diff produced by a `StateMutation`. | `VariableChanged<T>`, `ZoneContentRemoved`, `ZoneContentInserted`. Automatically produced by the state layer. |
| GameSignal | A `GameCommand` subtype (and `HistoryEntry`) recording a game-meaningful named fact that cannot be inferred from raw diffs alone. Not executable — trigger surface only. | `CardPlayStartedSignal`, `ActorHealedSignal`. Emitted explicitly by handlers via `scope.Emit(...)`. Replaces `SemanticEvent`. |
| GameAction | Executable `GameCommand` subtype — queued through the engine, runs through the full pipeline, modifiable in before-trigger fold. Atomic and synchronous: one handler, one envelope, returns a `CommandResult`. Never dispatches other `GameAction`s internally. | `PlayCardCommand`, `HealActorCommand`. Replaces the old `GameCommand` executable type. |
| CompositeMutation | Reusable group of state mutations. **Not a `GameCommand`** — lives outside the command family. Authored as `record X : CompositeMutation { void Apply(scope) }` and invoked via `scope.Execute(composite)` for inline expansion in the current scope. No queue, no envelope, no validator chain, no trigger fold. | `MoveCardComposite` (remove + insert + last-moved record as one logical cluster). Distinguished from Effect: a composite groups state mutations; an Effect sequences commands through `scope.Dispatch`. Per [ADR-0013](decisions/0013-engine-pipeline-orchestration.md). Supersedes the pre-cascade `CompositeAction` sibling of `GameCommand`. |
| Effect | Async orchestration layer that sequences multiple `GameAction`s and threads their `CommandResult`s. The only layer that can dispatch a series of commands. Defined on or referenced from a card/ability definition. | Play fireball: request target → deal damage → move to discard. See [features/effects/models/01-effect.md](features/effects/models/01-effect.md). |
| Decision | Explicit moment where an actor may or must choose from legal options. Modelled as a `GameAction` (`RequestTargetAction`, `RequestChoiceAction`) that opens the decision and returns the choice in its `CommandResult`. | Choose target, choose reward, pass priority, select event branch. |
| DecisionOption | One legal choice inside a decision. | May include ID, display info, target requirements, payload shape, or validation context. |
| Validation | Process of checking whether a command or option is legal in current state. | Enough energy, valid target, actor has priority, destination is legal, recipe exists, card is not exhausted. |
| OnBefore\<T\> | Before-trigger fold that runs before a `GameCommand` handler. `GameAction` payloads can be modified, cancelled, or replaced. | Validate, cancel, replace, redirect, or modify a game action before state changes. Replaces `CommandPreHook`. See [features/triggers/models/01-trigger.md](features/triggers/models/01-trigger.md). |
| OnAfter\<T\> | After-trigger fold that runs after a `GameCommand` handler. Reactions dispatched into the dispatch channel. | Draw a card when another card is healed. Trigger lifecycle effects. |
| CommandHandler | Resolver for a game command. | Reads state, applies state mutations, returns result. |
| CommandResult | Structured outcome of a game command. | Approved, rejected, actual destination, damage split, drawn instance ID. |
| GameRulesDefinition | Pure `[SerializeField]`-bearing data class (non-`UnityObject`) carrying authored config for a game-mode variant (starting life, hand size, format knobs). Asset-friendly; replay/save/network-safe. Wrapped by a Unity-side asset (e.g. `GameRulesAsset : ScriptableObject`) for editor assignability. | One per game-mode variant — Standard, Commander, Pauper as three definition assets sharing one runtime class. See [Game Rules Definition](features/engine/models/02-game-rules-definition.md). |
| GameRulesRuntime\<TDefinition\> | Stateful runtime brain plugged into the engine. Generic on its definition type; concrete runtimes (`MagicRulesRuntime : GameRulesRuntime<MagicRulesDefinition>`) get a typed `Definition` without casting. Holds framework services (`IStateScope`) plus game-specific subsystems via constructor injection. Implements `Evaluate(action, result) → MatchState` (state-based follow-up — returns the next `MatchState`, per [ADR-0009](decisions/0009-engine-as-fsm.md)) — the **single virtual hook** the framework provides. Exposes abstract `Flow : ITurnFlow`. Drain-policy composition (open requests pause transitions; pending effects drain) layered on top. Effect-firing routes through `PendingEffectsSlice` — runtime does not call the effect pipeline directly (per [ADR-0011](decisions/0011-effect-orchestration-dispatch-requests.md)). Trigger eligibility lives on `Trigger<T>.Validate` (per [ADR-0013](decisions/0013-engine-pipeline-orchestration.md)); `FilterTriggers` retired. `StateBasedActions` retired (see ISBA in retired terms) — game-specific cross-cutting checks live inside the game's `Evaluate` override using whatever pattern they choose. | Replaces the older single-type `GameRules` and the `IAvailableActions` snapshot writer. Engine is the framework loop; `GameRulesRuntime` is the game-specific plugin. DI-resolved per match via container open-generic resolution: game installer registers `Register<GameRulesRuntime<MagicRulesDefinition>, MagicRulesRuntime>()`; factory resolves via `MakeGenericType(definition.GetType())`. Single-phase construction (no Initialize hook). Engine owns disposal. See [Game Rules Runtime](features/engine/models/03-game-rules-runtime.md); [ADR-0009](decisions/0009-engine-as-fsm.md) for FSM evaluation + transitions, [ADR-0011](decisions/0011-effect-orchestration-dispatch-requests.md) for effect-firing layering + drain policy, [ADR-0013](decisions/0013-engine-pipeline-orchestration.md) for orchestration. |
| IGameFactory | DI-resolved framework service that constructs a fresh `GameEngine` for a match. Caller never sees VContainer; framework + game services are injected on the factory. Exposes both `Create(MatchSetup)` and `NewMatch()` (fluent). | See [Game Factory](features/engine/models/05-game-factory.md). The factory is the single public match-construction surface; behaviors come from the installer, match data flows through the factory. |
| MatchSetup | Per-match data bundle the factory consumes: `GameDefinition`, `Actors`, `Seed`, plus three optional overlays — `InitialSlices`, `ZoneOverlay`, `PlayerDefinitionOverlay`. | `Rules` no longer lives here directly — it's carried inside `GameDefinition` (per Q9). Per-match data only — never carries handler/mutator/intent-mapper/runtime types (those live in the VContainer installer). See [Game Factory](features/engine/models/05-game-factory.md). |
| IMatchBuilder | Fluent builder surface exposed by `IGameFactory.NewMatch()` as ergonomic sugar over `MatchSetup`. | `WithGame(GameDefinition)` / `WithActors` (params + IEnumerable) / `WithSeed` / `WithInitialSlices` / `WithZoneOverlay` / `WithPlayerDefinitionOverlay` / `Build`. Either `IMatchBuilder` or direct `MatchSetup` produces the same `GameEngine`. See [Game Factory](features/engine/models/05-game-factory.md). |
| ZoneOverlay | Optional `MatchSetup` overlay carrying additional `(ZoneDefinition, owner)` pairs to spawn beyond the standard layout in `GameDefinition.SharedZones` / `PlayerDefinition.PerPlayerZones`. | Used for scripted scenarios, tests, and games that need per-match zone variation (Stacklands sandbox modes, MTG limited-format puzzles). Definitions own the *common* layout; overlay is the escape hatch. |
| PlayerDefinitionOverlay | Optional `MatchSetup` overlay providing per-actor `PlayerDefinition` overrides for asymmetric games. `Dict<IActor, PlayerDefinition>`. | Symmetric games (most card games) leave this empty and the factory applies `GameDefinition.DefaultPlayerDefinition` to each player actor. Asymmetric games (different heroes, different roles) populate the overlay to give specific actors their specific definitions. |

| Term         | Short Definition                                                          | Examples / Notes                                                                                                     |
| ------------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Simulation   | Rules and state layer that decides what happens.                          | Owns entities, runtime definitions, commands, validation, effects, triggers, state changes, and history.             |

## Conventions

- **Objects over IDs.** Framework APIs prefer domain objects (`Zone`, `Card`, `EntityInstance<TDef>`, `Player`, `Actor`) over raw `Identifier<T>` values. IDs are reserved for boundaries — serialization, persistence, network transport, type-mismatch fallbacks. Stable subscription keys (triggers/effects/attachments) use the typed `Ref<T>` so they survive `CardRef` rotations. Within the simulation, code holds and passes the object; the object is also used as the key for slice access (`state.Get<X>(zone)`). See [ADR-0005](decisions/0005-objects-over-ids.md).
- **`CardRef` vs `Ref<Card>`.** Server-internal references (triggers, effects, attachments, history dispatch) use `Card` objects or `Ref<Card>` — never `CardRef`. Client-visible state (zones, indices, projections) uses `CardRef`. The split is the framework's privacy mechanism: rotating `CardRef` on hide/move propagates through client-visible state without breaking server-internal subscribers. `CardMapState` is the indirection layer that maps the rotating `CardRef` back to the stable `Ref<Card>`; the live `Card` handle resolves one further hop via `store.Catalog.Resolve(refOfCard)`. `CardRegistry` is retired (open-seams pass Q5).

## Nuance Notes

- Variables are key-value based. The base framework should not hardcode variable names; games, presets, schemas, or authoring packages define them.
- "Identity" is not a separate core concept. Use `Instance` (concretely: `EntityInstance<TDef>`); typed runtime identity is `Ref<T>`; use `Identifier<T>` for boundary forms (serialization, transport).
- Zone membership does not define an instance. Zone movement preserves the same instance by default.
- Zones are thin domain objects; their state lives in slices. They do not have stats — stat-bearing things are not zones.
- Card packs are not zones — they are entities with generator effects. Reward offers and drafts are decisions, not zones.
- Zones do not own broad gameplay legality; game/action rules decide whether movement is allowed.
- Spatial placement is not a base zone concern unless a game-specific spatial system makes it simulation data.
- UI creates `PlayerIntent`s and reacts to state/history; it should not mutate simulation state directly.
- History envelopes preserve why state changes happened, not only what changed.
- History is canonical on the server; per-actor views are produced at the transport boundary by ID translation + detail-visibility gating. Movement entries are always sent (fact-of-movement is public); card-detail entries are gated on visibility.
- `StateChange` entries are produced automatically by the state layer; `GameSignal` entries must be emitted explicitly by handlers via `scope.Emit(...)` for meanings the layer cannot infer.
- Every entity should have a base definition, including generated tokens or temporary system entities.
- Attachments and equipment are usually separate instances connected through relationships, not hidden fields on the host.
- `CommandReaction` (post-result pipeline hooks) is removed. Follow-up commands return from `GameRulesRuntime.Evaluate`.
- `Controller` and `Viewer` are not framework concepts. Controller is a generic system term; visibility queries take an `Actor` parameter directly with no typed `Viewer` wrapper.
